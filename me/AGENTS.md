# AGENTS.md — /me/ (Zone 1: Understanding)

> *"Don't delegate understanding."* — kepano (steph ango).
> The parts of the vault that define your thinking stay human-authored.

---

## The Rule

**Annotate only. Never rewrite.**

Files in `/me/` capture the operator's voice, doctrine, journey, profile, and strategy. These are the substrate of the operator's identity-as-thinker. The vault loses sovereignty if agents silently rewrite them.

If an agent thinks a `/me/` file needs revision: **propose to the user in chat**. Wait for explicit instruction to edit. Don't draft a rewrite preemptively.

---

## Exceptions (Zone 2 files in /me/)

These specific `/me/` files are co-authored. Agents MAY update them in place with explicit routing plans:

- `/me/vault-todo.md` — phased task list
- `/me/content-plan.md` — content strategy layer
- `/me/system-patterns.md` — append patterns under existing sections, never restructure

For these files: **routing plan still mandatory** before any write.

---

## Strict Zone 1 (annotation-only)

These files are human-authored under all circumstances. Agent never edits them.

- `/me/doctrine.md` — named principles with empirical evidence
- `/me/voice.md` — writing voice and tone directives
- `/me/profile.md` — self-knowledge / positioning
- `/me/obsidian-strategy.md` — vault architectural decisions
- `/me/vault-guide.md` — onboarding reference
- `/me/playbooks/*.md` — personal-authored playbooks
- `/me/published/_INDEX.md` — append-only published log
- `/me/ideas/_INBOX.md` — append entries; don't reorder existing
- `/me/drafts/*.md` — content drafts; agent helps on explicit invitation

---

## When Suggesting Changes to Zone 1 Files

1. **Surface in chat** with the observation
2. Wait for explicit "yes" or specific instruction
3. Show the proposed edit BEFORE writing
4. Wait for "confirm" / "go" / "proceed"
5. Then write

The slowness is the feature. Zone 1 is where the operator's judgment lives.
