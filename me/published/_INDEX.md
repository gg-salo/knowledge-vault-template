# Published Content Index

>
> Every entry links back to the idea it came from (if captured in `_INBOX.md`), the projects referenced, and the doctrine expressed. This is how the vault tracks which parts of your thinking have been externalized — and which haven't.

---

## How to Add an Entry

Use `log published: [first line of the piece]` in any Claude Code session at vault root. Claude will append a new entry using this format:

```markdown
### YYYY-MM-DD — [First line or headline of the published piece]
- **Platform:** [X / LinkedIn / Newsletter / Blog / Other]
- **Link:** [URL]
- **Pattern:** [Abstract-level description]
- **Doctrine expressed:** [[doctrine-name]] (or "none" if not tied to a doctrine)
- **Project referenced:** [[project-name]] (or "none")
- **Origin idea:** [[_INBOX]] #N (if captured before publishing)
- **Signal:** [views / engagement / responses — update a week later]
- **Notes:** [Optional — what worked, what didn't, follow-up angles]
```

## Why This File Exists

Publishing is the test of whether your doctrines hold up in the wild. This log surfaces two things:

1. **What's been externalized vs. what's still trapped in the vault** — weekly synthesis workflows scan this file against `doctrine.md` and `_INBOX.md` to surface unexpressed patterns.
2. **Signal tracking** — which pieces landed, which didn't, and why. Pattern-level grouping shows you which *kinds* of ideas resonate, not just which specific ones.
