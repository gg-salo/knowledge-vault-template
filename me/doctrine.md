## What a Doctrine Is

A **named principle** you've observed repeatedly in your own work, with evidence.

It is NOT:
- A rule you read in a book
- Generic advice ("ship fast", "focus")
- A principle you wish were true

It IS:
- A pattern you've seen play out at least 2–3 times
- Something you can cite specific evidence for
- Opinionated and memorable (the name matters — it's how you'll reference it later)

When you add a doctrine, Claude will reference it in reviews, strategy sessions, and adversarial critiques. The doctrine file is the canonical location for your judgment.

---

## Format for Each Doctrine

```markdown
## [Doctrine Name]
> [One-line description that captures the principle]

- **Where first observed:** [situation/project where you noticed it]
- **Evidence:**
  - [Specific example 1 — project, situation, outcome]
  - [Specific example 2]
  - [Specific example 3]
- **Confidence:** low | medium | high
- **Strategic implication:** [optional — what this changes about how you operate]
- **External validation:** [optional — where you've seen this echoed by others]
```
